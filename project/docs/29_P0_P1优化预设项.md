# P0 / P1 优化预设项

状态：计划，未实施  
范围：只改 loader / HLE / 呈现层，不改游戏引擎  
基线：2.3.0.2  
目标：先修 2.3 的已知回退，再把 D3D9Ex 的呈现能力用完整；DXGI、插值、frame generation 不列入本轮。

## 一、P0：先修已知回退

### P0-1 窗口 / 无边框改用 DWM 时钟

**问题**

- 60Hz 窗口 / 无边框的实际显示路径是 DWM；
- 当前 `frame_clock` 优先跟随扫描线；
- 扫描线和 DWM 合成可能有相位差，tick 对扫描线、Present 对 DWM，体感可能不如 2.2.37.13 的 `DwmFlush`。

**改动**

- 真全屏：继续优先扫描线；
- 窗口 / 无边框：优先 `DwmGetCompositionTimingInfo` 的 vblank / refresh；
- DWM 不可用或不稳：退回扫描线或固定 timer；
- 先加 A/B 诊断开关，不要直接改默认。

**验收**

- 60Hz 窗口 / 无边框重复 / 丢帧不高于 2.3.0.2；
- 主观体感不差于 2.2.37.13；
- 120 / 240 / VRR 不因来源切换变差。

**风险**

- DWM 时间戳可能延迟、遮挡时不更新；
- 影响面涉及所有非独占模式，需要完整测试矩阵。

### P0-2 模式切换时重置低延迟 early 状态

**问题**

- `present_before_tick()` 的 `early` / `would_make` 是 static；
- Alt+Enter / device reset 不重置；
- 切窗口期间保持 false，回全屏后继续 false，要连续 120 帧才恢复。

**改动**

- 在进入 / 离开真全屏、device reset、vsync 状态变化时重置：
  - `early = true`
  - `would_make = 0`
- 只在模式 / 设备变化时做，不能每帧做，否则破坏 120 帧防抖。

**验收**

- Alt+Enter 回真全屏后，低延迟不长期停在 false；
- 普通 miss 仍然要经过恢复门限，不因重置而频繁提前。

### P0-3 放宽容忍 120 帧恢复

**问题**

- 当前要求连续 120 帧都赶得上，一次 miss 就归零；
- 小卡、载入、驱动抖动会让它长期不恢复。

**改动**

- 方案 A：最近 120 帧允许少量 miss；
- 方案 B：最长关闭 2 秒后强制重试一次；
- 方案 C：用衰减计数代替硬归零。

优先 A，保留现有 120 帧语义但不再“一次 miss 全清”。

**验收**

- 正常场景恢复时间不超过约 2 秒；
- 重帧场景不会无限期停在 false；
- 不增加明显重复 / 丢帧。

### P0-4 hold 只保留在真正需要的地方

**问题**

- 固定 144 / 165Hz 也会 hold 约 5ms；
- 120 / 240 开“稳定游戏速度”后也会 hold；
- 固定刷新不是 VRR，hold 不一定改善均匀度，却一定增加延迟。

**改动**

- VRR / `FollowsUs`：保留 hold；
- 固定 144 / 165：默认不 hold；
- 120 / 240 正常跟随时不 hold；
- 固定高刷若要 hold，必须可配置或有实测收益。

**验收**

- 固定 144 / 165 延迟下降；
- VRR 的 frame gap 不明显变差；
- 60Hz 不受影响。

### P0-5 减少 Alt+Enter 旧画面和第二次 Reset

**问题**

- 日志显示一次全屏→窗口 Reset 约 1.3 秒；
- restyle 后 DWM 先显示旧窗口表面；
- 第一个 Present 返回 `S_PRESENT_MODE_CHANGED`，又触发一次 Reset；
- 玩家会看到旧画面约 0.5–2 秒。

**改动**

- restyle 前隐藏窗口或清黑；
- 等第一帧新画面再显示；
- 评估 `S_PRESENT_MODE_CHANGED` 的第二次 Reset 是否必要；
- 至少避免第二次 Reset 把旧表面停留时间拉长。

**验收**

- 全屏→窗口不再显示很久之前的画面；
- 切换总时间不增加；
- 不引入黑屏闪烁或焦点问题。

## 二、P1：把 D3D9Ex 用完整

### P1-1 PresentStats

**改动**

- 创建 device 时加 `D3DCREATE_ENABLE_PRESENTSTATS`；
- 失败则不带 flag 重试；
- 取 `IDirect3DSwapChain9Ex`，Present 后读 `GetPresentStats`；
- 用 `SyncQPCTime` / `PresentRefreshCount` 校正 hold 和 deadline；
- stats 不可用时回退当前估算。

**验收**

- hold 估算误差下降；
- 窗口 / 真全屏都不因 stats 缺失而不稳；
- 不增加明显 CPU 开销。

**风险**

- 窗口 / DWM 下 stats 可能不可用或不准确；
- 需要处理 flag 创建失败。

### P1-2 Frame latency

**改动**

- 评估 `SetMaximumFrameLatency(1)`；
- 只在兼容的 flip 路径启用；
- 失败静默回退。

**验收**

- 输入到 Present 延迟下降；
- 不增加重复 / 丢帧。

### P1-3 WaitForVBlank fallback

**改动**

- 在扫描线 / DWM 都不可用时，用 `WaitForVBlank` 作为最后兜底；
- 不在主路径每帧阻塞。

**验收**

- 极端环境仍能稳定 60；
- 不引入额外阻塞。

### P1-4 FLIPEX A/B

**改动**

- 窗口 / 无边框试 `D3DSWAPEFFECT_FLIPEX`；
- 保留 COPY 作为回退；
- 先 A/B，不直接默认。

**验收**

- Present 延迟 / 重复帧有改善才保留；
- DWM / 多螢幕 / 錄影 / 遮擋不出問題。

### P1-5 高刷策略整理

**改动**

- 120 / 240：正常跟随，每 2 / 4 次刷新一拍；
- 144 / 165：默认切 60；不切则固定 timer；
- VRR：可配置 hold / at-once；
- 所有策略在日志里写明当前选择和原因。

**验收**

- 120 / 240 不因“全屏时用 60Hz”被切；
- 144 / 165 不出现 3 / 2 交替；
- VRR 不再无条件 hold。

## 三、实施顺序

```text
1. P0-2 early 状态重置
2. P0-3 120 帧恢复放宽
3. P0-1 窗口 DWM 时钟 A/B
4. P0-4 hold 范围
5. P0-5 切换旧画面 / 第二次 Reset
6. P1-1 PresentStats
7. P1-2 Frame latency
8. P1-4 FLIPEX A/B
9. P1-3 WaitForVBlank fallback
10. P1-5 高刷策略收尾
```

理由：

- P0-2 / P0-3 代码小、风险低，先解决实机最痛的 Alt+Enter 问题；
- P0-1 影响面大，必须 A/B；
- P0-4 需要体感 / 量测一起判断；
- P1 在 P0 稳定后再做，避免同时改变太多变量。

## 四、测试矩阵

| 场景 | 必测 |
|---|---|
| 60Hz 窗口 | 启动、稳定、Alt+Enter 往返 |
| 60Hz 无边框 | 启动、稳定、切窗口 |
| 60Hz 真全屏 + vsync on | 低延迟 / 普通 |
| 60Hz 真全屏 + vsync off | 撕裂位置 |
| 120 / 240 窗口 / 无边框 | 2 / 4 次刷新 |
| 144 / 165 无边框切 60 | 进入 / 最小化 / 返回 / 退出 |
| 144 / 165 真全屏切 60 | 进入 / 退出 |
| VRR | hold / no hold |
| Alt+Enter 全链路 | 窗口→无边框→窗口→真全屏→窗口 |
| 多螢幕 / 遮擋 / 最小化 | DWM 來源與還原 |

## 五、不列入本轮

```text
整个 HLE 改 D3D11 / D3D12
DXGI shared texture 桥接
frame generation / 插值
重新设计 renderer
```

這些不是優化，是重寫；等 P0 / P1 有數據後再評估。

## 六、完成标准

```text
P0 全部完成，且 60Hz 窗口 / 无边框不低于 2.2.37.13 的体感
Alt+Enter 后低延迟不长期卡 false
固定 144/165 不再默认多 5ms
切换不再显示很久之前的旧画面
P1 至少完成 PresentStats 与 frame latency 的 A/B
```

任何一项若实测没有收益，记录数据后撤回，不为了“做过”而保留。

## 七、逐项假设、疑问与验证

本节是这份文档最重要的部分：P0 / P1 都是假设，不是已证实的结论。  
没有完整审计全部 D3D8→D3D9 HLE、所有 D3D9Ex / DWM / 驱动分支；以下每项都要先验证再改默认。

### P0-1 窗口 / 无边框改用 DWM 时钟

**假设**

- 窗口 / 无边框的实际显示路径是 DWM；
- 扫描线和 DWM vblank 存在相位差；
- tick 跟扫描线、Present 走 DWM，会造成重复 / 丢帧或主观不順。

**疑问**

- 相位差到底多大？目前没有量到“扫描线 vs DWM”的差值分布；
- DWM 时间戳是否比扫描线更贴近实际显示？
- DWM 被遮挡 / 最小化 / 多螢幕时是否还可靠？
- 120 / 240 下 DWM 是否真的按该刷新率合成？
- VRR 下 DWM 时间戳是否稳定？
- 会不会只是低延迟 / Alt+Enter 造成的体感差异，而不是时钟来源？

**验证**

- 加 `window_clock = dwm / scanline` 诊断开关；
- 同一场景记录两种来源的 vblank、相位差、重复 / 丢帧；
- 60Hz 窗口 / 无边框各跑同一段；
- 再做 120 / 240 / VRR / 遮挡 / 最小化；
- 没有数据前不改默认。

**可能的错误**

- DWM 时间戳更差；
- 换来源后 120 / 240 變差；
- 真正的问题不是来源，而是低延迟状态或 Alt+Enter。

### P0-2 模式切换时重置 early

**假设**

- `early` / `would_make` 是 static，模式切换不会重置；
- 切窗口期间保持 false，回全屏后要重新凑 120 帧；
- 这是 Alt+Enter 后延迟高的主因。

**疑问**

- 作者是否故意让状态跨模式保留？
- 每次 Reset 都重置，会不会让重帧场景频繁提前、增加重复 / 撕裂？
- vsync 状态变化时也要重置吗？
- 只重置 `early`，还是 `would_make` 也一起归零？

**验证**

- 在日志里记录模式切换前后的 `early` / `would_make`；
- Alt+Enter 往返，观察低延迟恢复时间；
- A/B：重置 vs 不重置；
- 确认普通 miss 的 120 帧防抖仍然有效。

**可能的错误**

- 重置太频繁，低延迟反而更不穩；
- 真正卡住的是 deadline 或 clock，不是 early。

### P0-3 放宽容忍 120 帧恢复

**假设**

- 连续 120 帧、一次 miss 归零太严格；
- 小卡 / 载入 / 驱动抖动会让它长期不恢复；
- 滚动窗口或允许少量 miss 更合理。

**疑问**

- 作者要的“连续 120 帧”是否必须严格？
- 允许几次 miss 才不影响画面？
- 强制 2 秒重试会不会让重帧场景反复提前？
- 放寬后是否增加重复 / 撕裂？

**验证**

- 记录 strict / relaxed 的提前比例、miss 分布、重复 / 丢帧；
- 在轻 / 中 / 重场景各跑一次；
- 比较恢复时间和画面稳定性。

**可能的错误**

- 放寬后低延迟频繁开回，画面更差；
- 真正的恢复问题来自 early 状态没重置，而不是 120 太严。

### P0-4 固定 144 / 165 不預設 hold

**假设**

- 固定刷新不是 VRR，hold 不一定改善均勻度；
- hold 一定增加約 5ms 延遲；
- 固定 144 / 165 預設不 hold 比較好。

**疑问**

- 固定 144 / 165 的 hold 是否真的完全無效？
- 作者註解說固定刷新「whatever is done」都會不均，hold 是否仍然能減少變異？
- 關掉後 frame gap 會不會更差？
- 120 / 240 開穩定速度時也要不 hold 嗎？

**驗證**

- hold on/off 各跑 144 / 165；
- 記錄 frame gap 分佈、重複 / 丟幀、輸入延遲；
- 主觀 A/B；
- 120 / 240 + 穩定速度另外測。

**可能的錯誤**

- 固定 144 / 165 的 hold 其實有幫助；
- 關掉後畫面更抖，只是延遲降低；
- 不同驅動 / 螢幕結果不同。

### P0-5 減少切換舊畫面與第二次 Reset

**假設**

- restyle 後 DWM 先顯示舊窗口表面；
- 第一個 Present 的 `S_PRESENT_MODE_CHANGED` 導致第二次 Reset；
- 第二次 Reset 不必要，或可以避免。

**疑問**

- 第二次 Reset 是否其實是清除 mode changed 的必要步驟？
- 隱藏窗口 / 清黑會不會造成黑屏閃爍或焦點問題？
- 舊畫面是 DWM 表面，還是 back buffer / dirty rect？
- 1.3 秒 Reset 本身是否主要成本，而不是第二次 Reset？

**驗證**

- 記錄 restyle、第一個 Present、第二次 Reset 的時間；
- 嘗試隱藏 / 清黑 / 延後顯示；
- 確認不移除第二次 Reset 也能縮短舊畫面；
- 量切換總時間與焦點 / 黑屏。

**可能的錯誤**

- 移除第二次 Reset 後 Present 持續失敗；
- 舊畫面其實不是 DWM 表面；
- 真正成本是 ResetEx，而不是第二次 Reset。

### P1-1 PresentStats

**假設**

- D3D9Ex 的 `GetPresentStats` 能提供更準的顯示時間；
- 可以改善 hold / deadline 估算；
- 窗口 / 真全屏都能用。

**疑問**

- `D3DCREATE_ENABLE_PRESENTSTATS` 是否所有驅動都支援？
- 窗口 / DWM 下 stats 是否可用？
- stats 是否延遲一幀以上？
- `SyncQPCTime` 和現有 clock 怎麼對齊？
- 拿不到 stats 時 fallback 是否完整？

**驗證**

- 带 flag / 不带 flag 建立 device；
- 真全屏 / 窗口各讀 stats；
- 對比 `PresentRefreshCount` 和現有 vblank；
- 確認 stats 缺失時不影響 60Hz。

**可能的錯誤**

- 窗口 stats 不可用，收益只限真全屏；
- stats 延遲太大，反而帶歪 clock；
- flag 導致 device 建立失敗。

### P1-2 Frame latency

**假設**

- `SetMaximumFrameLatency(1)` 可以減少排隊、降低延遲；
- 對 flip 路徑有效。

**疑問**

- D3D9Ex 的 frame latency 對獨佔 / 窗口是否都有效？
- 設 1 會不會增加 stutter / 重複？
- 是否和 DWM / 驅動衝突？

**驗證**

- 0 / 1 / 2 各跑一次；
- 量輸入到 Present、重複 / 丟幀；
- 不支援時靜默回退。

**可能的錯誤**

- 只對窗口有效；
- 設 1 反而更容易 miss。

### P1-3 WaitForVBlank fallback

**假設**

- 掃描線 / DWM 都不可用時，`WaitForVBlank` 可以作為最後兜底。

**疑問**

- 窗口模式是否支援？
- 會不會阻塞主執行緒？
- 和 timer fallback 哪個更穩？

**驗證**

- 強制停用掃描線 / DWM，測 fallback；
- 量 frame gap、阻塞時間；
- 只在必要時使用。

**可能的錯誤**

- 窗口不支援；
- 阻塞造成更大 jitter。

### P1-4 FLIPEX A/B

**假設**

- D3D9Ex `FLIPEX` 可以少一次 COPY、降低窗口延遲；
- 可能改善 frame pacing。

**疑問**

- DWM 是否仍主導顯示？
- 多螢幕 / 錄影 / 遮擋 / 最小化是否相容？
- 和現有 COPY 路徑相比是否真的更好？
- D3D9Ex FLIPEX 在 Win32 視窗的支援度如何？

**驗證**

- 先做 A/B，不預設默認；
- 量延遲、重複 / 丟幀、相容性；
- 保留 COPY 回退。

**可能的錯誤**

- 沒有收益；
- DWM 路徑不相容；
- 多螢幕 / 錄影出問題。

### P1-5 高刷策略整理

**假設**

- 120 / 240 正常跟隨、144 / 165 切 60、VRR 可配置，是比較合理的策略。

**疑問**

- 作者是否要保留 144 / 165 的高刷選項？
- VRR 要預設 hold 還是 at-once？
- 120 / 240 在穩定速度下要不要 hold？
- 75 / 50 怎麼處理？

**驗證**

- 每種刷新率跑跟隨 / 切 60 / 固定 timer；
- 量 frame gap、延遲、模式切換副作用；
- 再定默認。

**可能的錯誤**

- 144 / 165 強制切 60 對某些玩家是倒退；
- VRR 不 hold 更不穩；
- 75 / 50 被忽略。

## 八、驗證前的結論

```text
P0-2、P0-3 程式依據較強，但仍需 A/B
P0-1、P0-4、P1-1、P1-4 風險最高，沒有數據前不應改默認
P0-5 需要先確認第二次 Reset 是否必要
P1-2、P1-3、P1-5 是候選方案，不是定案
```

下一步不是直接實作，而是先加診斷與量測：

```text
1. window_clock = dwm / scanline
2. hold = on / off
3. early reset = on / off
4. 120 strict / relaxed
5. PresentStats = on / off
```

每項都要有：

```text
重複 / 丟幀
frame gap
輸入到 Present
Alt+Enter 往返
主觀 A/B
```

沒有數據的項目，留在文件裡，不進預設。
